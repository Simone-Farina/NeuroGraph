**File 1: `supabase/migrations/20260322000000_knowledge_queue.sql`**

Create the `knowledge_queue` table with these exact columns:
- `id` UUID PRIMARY KEY DEFAULT gen_random_uuid()
- `user_id` UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE
- `title` TEXT NOT NULL
- `url` TEXT (nullable -- pure thoughts have no URL)
- `notes` TEXT (nullable -- optional user annotation)
- `state` TEXT NOT NULL DEFAULT 'inbox' CHECK (state IN ('inbox', 'passive_debt', 'resource', 'mastered'))
- `source_domain` TEXT (nullable -- auto-extracted from URL on capture in Phase 6)
- `favicon_url` TEXT (nullable -- auto-extracted from URL on capture in Phase 6)
- `estimated_read_time` INTEGER (nullable -- minutes; auto-extracted on capture in Phase 6)
- `created_at` TIMESTAMPTZ NOT NULL DEFAULT NOW()
- `updated_at` TIMESTAMPTZ NOT NULL DEFAULT NOW()

Use a CHECK constraint (NOT a PostgreSQL ENUM) for the state field per research recommendation.

Enable RLS with an idempotent `FOR ALL USING (auth.uid() = user_id)` policy named "Users can CRUD own queue items" using the DO $$ BEGIN IF NOT EXISTS pattern from existing migrations.

Create a partial composite index: `idx_knowledge_queue_user_active ON knowledge_queue(user_id, state, created_at DESC) WHERE state != 'mastered'` to optimize the active queue query.

Create an `update_knowledge_queue_updated_at()` trigger function and trigger to auto-update `updated_at` on row change.

**File 2: `supabase/migrations/20260322000001_user_api_keys.sql`**

Create the `user_api_keys` table with these exact columns:
- `id` UUID PRIMARY KEY DEFAULT gen_random_uuid()
- `user_id` UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE
- `key_prefix` TEXT NOT NULL (stores "ng_" + first 8 chars of raw key for display)
- `key_hash` TEXT NOT NULL UNIQUE (SHA-256 hex digest; never stored plaintext)
- `created_at` TIMESTAMPTZ NOT NULL DEFAULT NOW()
- `last_used_at` TIMESTAMPTZ (nullable -- updated on each valid API call)
- `revoked_at` TIMESTAMPTZ (nullable -- NULL = active, non-null = revoked)

Enable RLS with TWO narrow policies (NOT a single FOR ALL):
1. "Users can read own keys" -- `FOR SELECT USING (auth.uid() = user_id)`
2. "Users can delete own keys" -- `FOR DELETE USING (auth.uid() = user_id)`

No INSERT or UPDATE policy -- INSERT is done by the service role client (bypasses RLS), UPDATE (for last_used_at) is done by service role in the capture endpoint.

Create a partial unique index: `idx_user_api_keys_active_per_user ON user_api_keys(user_id) WHERE revoked_at IS NULL` to enforce max 1 active key per user at the database level.

**CRITICAL: Do NOT add a fifth state (no 'crystallizing', no 'discarded'). CONTEXT.md locked exactly 4 states.**
**CRITICAL: Column name is `key_hash` (not `hashed_key`) -- consistent across all files.**

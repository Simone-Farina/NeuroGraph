# Phase 11.5: Horizon UI & DAG Wiring - Context

**Gathered:** 2026-03-23
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 11.5 is the runtime bridge between the approved Architect contract and the product shell.

This phase introduces an authenticated `/api/architect` route that returns ephemeral curriculum drafts, a graph-side `Set Learning Target` trigger, ghost-node rendering in React Flow, and a left-panel briefing mode that can hand a ghost concept into chat.

This phase does not persist draft nodes or synapses to Supabase, implement a final `Commit Path` flow, or replace the upcoming Bouncer / Socratic agent phases.

</domain>

<decisions>
## Implementation Decisions

### Roadmap integrity
- This work is inserted as Phase 11.5.
- Phase 12 remains the Chat Analyzer / Bouncer agent.

### Persistence model
- `/api/architect` returns the strict Architect JSON contract directly to frontend state.
- No draft nodes or synapses are written to Supabase in this phase.
- The persistent graph remains untouched until a later explicit commit flow exists.

### Trigger surface
- The target-setting entry point belongs in GraphPanel chrome, not in chat.
- The trigger label is `Set Learning Target`.
- The interaction should feel elegant and low-anxiety, not like a modal-heavy wizard.

### Ghost-node behavior
- Register a `ghostNeuron` React Flow node type.
- Style it as Fog of War:
  - muted palette
  - dashed 1px borders
  - reduced opacity
  - visible title
  - blueprint feel
- Ghost nodes are preview artifacts, not editable neurons.

### Ghost click handoff
- Clicking a ghost node switches the left panel into a briefing mode.
- The briefing shows the AI-generated definition and a primary `Start Learning (Crystallize)` CTA.
- That CTA seeds a fresh chat session with the selected concept as the learning target.

### Shell behavior
- Reuse the existing named shell presets.
- Do not introduce drag resizing or new persistent layout complexity in this phase.

</decisions>

## Existing Code Insights

- `GraphPanel` currently loads only persisted neurons from `/api/neurons` and registers only the `neuron` node type.

**File 1 — `src/components/chat/MessageList.tsx` (primary fix):** Find the `toolState` derivation (around line 127-128):
```typescript
const toolState: 'call' | 'result' =
  toolPart.state === 'output-available' ? 'result' : 'call';
```
Change to:
```typescript
const toolState: 'call' | 'result' =
  (toolPart.state === 'output-available' || toolPart.state === 'input-available')
    ? 'result'
    : 'call';
```
This is safe because: (a) freshly streaming tool calls have `state: 'partial-call'`, never `'input-available'`; (b) `input-available` only appears in rehydrated messages from `loadMessages` (ChatPanel line 298), which are always already-committed neurons.

**File 2 — `src/components/chat/NeurogenesisSuggestion.tsx` (defensive guard per D-05):** After the existing `isInputComplete` check, add a streaming guard so that even if a fresh live tool call somehow reaches this path, it shows the spinner:
```typescript
const isStreaming = state === 'partial-call';
```
Update the early spinner return to: `if (!isInputComplete || isStreaming) { return <spinner>; }`

This ensures the component treats any tool call that is not actively streaming as complete when input is available, per D-05's intent.

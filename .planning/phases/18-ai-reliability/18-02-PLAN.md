    Per AI-01 and the CONTEXT.md decision that streamText errors are NOT thrown to outer try/catch (they silently swallow — confirmed AI SDK GitHub issue #4726), add the onError callback as the primary error surface.

    **Modify the streamText call at line 193 to add these three properties:**

    ```typescript
    const response = streamText({
      model,
      system: systemPrompt,
      messages: modelMessages,
      tools: {
        suggest_neurogenesis: suggestNeurogenesisTool,
      },
      maxRetries: 1,                              // Chat is interactive — 1 retry max (user is watching)
      abortSignal: AbortSignal.timeout(60_000),   // 60s — allows long Socratic exchanges
      onError: ({ error }) => {
        // This is the ONLY reliable way to log stream errors — they are NOT thrown to outer try/catch
        console.error('[chat/stream] Provider error during stream:', error);
      },
      onFinish: async (event) => {
        // Guard: if the stream was aborted mid-flight, event.text may be empty
        // Do NOT persist empty assistant messages
        if (!event.text.trim() && event.toolCalls.length === 0) return;
        if (!conversationId) return;

        // ... rest of existing onFinish logic (DB persistence) unchanged ...
      },
    });
    ```

    Specific changes:
    1. Add `maxRetries: 1` — chat streams should retry once on transient provider errors (429/500/503). Only 1 retry because the user is watching and a second retry adds dead silence.
    2. Add `abortSignal: AbortSignal.timeout(60_000)` — 60 second hard cap. Chat exchanges can be long, especially multi-turn Socratic dialogues.
    3. Add `onError: ({ error }) => { console.error('[chat/stream] Provider error during stream:', error); }` — this is the ONLY way to surface mid-stream provider failures. Without it, a 429 during streaming produces zero logs.
    4. Add empty text guard at the top of onFinish: `if (!event.text.trim() && event.toolCalls.length === 0) return;` — prevents persisting empty assistant messages when streams abort. Note: the current code already checks `if (!assistantText && toolInvocations.length === 0) return;` on line 214. Verify this guard exists and covers the abort case.     - Do NOT add any prompt changes
    - Do NOT import new modules — streamText is already imported from 'ai'

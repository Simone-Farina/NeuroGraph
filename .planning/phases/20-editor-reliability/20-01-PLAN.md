  <action>
    Three changes to LiquidDocumentEditor.tsx:

    **A. Fix content sync race (EDITOR-01):**
    Replace the TWO separate useEffects at ~line 202-216 with ONE unified effect keyed on `neuron.id`:

    ```typescript
    // Replace BOTH effects (lines 202-216) with this single effect:
    useEffect(() => {
      if (!editor) return;
      // Force-sync content on neuron ID change regardless of focus state
      editor.commands.setContent(neuron.content || '', false);
      setTitle(neuron.title || '');
      setIsDirty(false);
      setExtractedMeta(null);
      setExtractionState('idle');
      setAiOutput(null);
    }, [neuron.id, editor]);
    ```

    The second argument `false` to setContent prevents emitting an `update` event. Without it, TipTap v3 emits onUpdate by default, which triggers setIsDirty(true) and the 2.5s extraction debounce — causing a false extraction on every neuron switch.

    The `isFocused` guard in the old second effect was protecting against overwriting in-progress edits. That guard is wrong when `neuron.id` changes — an ID change always means a different neuron, so stale content must be discarded regardless of focus.

    Remove `neuron.title` from the old first effect's dependency array (it was `[neuron.id, neuron.title]`). Title syncs from the new neuron object, not from title changes within the same neuron.

    **B. Standardize save serialization to getJSON (EDITOR-02):**
    In `handleSave` (~line 218-230), change:
    ```typescript
    // OLD:
    content: editor.getHTML(),
    // NEW:
    content: JSON.stringify(editor.getJSON()),
    ```

    The `content` field is a `string` column in the database and the `onSave` prop expects `string`, so we JSON.stringify the TipTap JSON document. This is the canonical lossless format — HTML introduces XSS surface area and cannot round-trip reliably if extensions change.

    **C. Fix triggerExtraction to send HTML for semantic signal:**
    In `triggerExtraction` (~line 174-200), change the content sent to the extraction API:
    ```typescript
    // OLD:
    const content = editor.getText().trim();
    if (!title.trim() || content.length < 40) return;
    // ...
    body: JSON.stringify({ title, content }),

    // NEW:
    const textContent = editor.getText().trim();
    if (!title.trim() || textContent.length < 40) return;
    // ...
    body: JSON.stringify({ title, content: editor.getHTML() }),
    ```

    Keep getText() for the length check (correct — formatting doesn't count toward minimum length). But send getHTML() to the extraction API so the AI model sees headings, bullets, and emphasis — these carry semantic signal for Bloom classification. The extraction endpoint receives a string either way.

    **D. Backward-compatible content loading:**
    The `useEditor` initial content at line 138 (`content: neuron.content || ''`) already works for both formats because TipTap's `setContent` accepts both HTML strings and JSON objects/strings. When `neuron.content` is a JSON string, TipTap will parse it as a JSON document. When it is HTML (legacy data), TipTap parses it as HTML. No change needed here — but the unified effect in change A uses `neuron.content || ''` which also handles both formats via `setContent`.

    ```typescript

    ```

    **B. Fix the content sync equality check:**
    The useEffect at line 88-94 compares `content` (HTML string from prop) to `editor.getText()` (plain text) — these can never be equal, causing unnecessary setContent calls.

    ```typescript
    // OLD:
    useEffect(() => {
      if (!editor) return;
      const currentText = editor.getText();
      if (content !== currentText && !editor.isFocused) {
        editor.commands.setContent(content || '');
      }
    }, [editor, content]);

    // NEW:
    useEffect(() => {
      if (!editor) return;
      if (editor.isFocused) return;
      // Compare JSON serializations to detect actual content change
      const currentJson = JSON.stringify(editor.getJSON());
      const incoming = content || '';
      if (incoming !== currentJson) {
        editor.commands.setContent(incoming, false);
      }
    }, [editor, content]);
    ```

    This handles both legacy HTML content (compared as string) and new JSON content (compared as JSON string). The `false` second argument to setContent prevents triggering onChange on programmatic sync.

    NOTE: NeuronTipTapEditor is currently not imported anywhere in the codebase (LiquidDocumentEditor replaced it as the primary editor). However, it remains a public component and must be correct for future use and for EDITOR-02 compliance.

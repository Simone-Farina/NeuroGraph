<objective>
Create the POST /api/neurogenesis endpoint implementing a 3-step sequential pipeline: Synthesizer (distill conversation into canonical neuron), RAG (find similar neurons via vector search), and Epistemological Inquisitor (infer prerequisites). Each step gets its own Langfuse span for observability.

Purpose: This is the backend half of the decoupled architect pipeline — separating neuron creation from the chat flow into a dedicated, traceable endpoint.
Output: Working API route that accepts a conversationId and returns a persisted neuron with DAG edges.

Create src/app/api/neurogenesis/route.ts with:

1. Request schema: `z.object({ conversationId: z.string().uuid() })`

2. Auth: use `getAuthenticatedUser()` pattern (returns user + supabase client)

3. Wrap the entire pipeline in `observe('neurogenesis-pipeline', async () => { ... })` from tracing.ts for a parent Langfuse span. Add `buildTelemetry('neurogenesis-pipeline', { userId: user.id, conversationId })` on the outer level.

4. **Step 1 — Fetch messages server-side:**
   - Query `supabase.from('messages').select('id, role, content').eq('conversation_id', conversationId).order('created_at', { ascending: true })`
   - Filter to role = 'user' | 'assistant'
   - If no messages found, return 400 "No messages found for this conversation"

5. **Step 2 — Synthesizer (ARCH-02):**
   - Call `synthesize(messages, user.id)` from the new synthesizer module
   - If this fails, return 500 with error message (neuron cannot be created without title/definition — per CONTEXT.md)
   - The synthesize function already has its own telemetry span ('neurogenesis-synthesizer')

6. **Step 3 — Embedding + RAG (non-fatal):**
   - Generate embedding: `generateEmbedding(\`${synthesis.title} ${synthesis.definition} ${synthesis.core_insight}\`)`
   - Call `supabase.rpc('find_similar_neurons', { query_embedding: embedding, match_user_id: user.id, match_count: 10, match_threshold: 0.15 })`
   - Wrap RAG in try/catch — on failure, log warning and continue with empty candidates (per CONTEXT.md: create orphan neuron)

7. **Step 4 — Insert neuron:**
   - Follow the exact insert pattern from neurons/route.ts (lines 127-148): stability: 1.0, difficulty: 5.0, state: 'New', etc.
   - Include `source_conversation_id: conversationId`
   - Set `bloom_level: 'Analyze'` (the button only activates at Analyze+, so this is the minimum)
   - Use `.select('*').single()` to return the created neuron
   - Handle 23505 (duplicate title) with 409 response

8. **Step 5 — Inquisitor (non-fatal, per CONTEXT.md):**
   - If RAG returned candidates, fetch their full records (id, title, definition)
   - Call `inferPrerequisites(synthesis, candidateNeurons, user.id)` — already has its own telemetry span ('inquisitor')
   - Call `createPrerequisiteSynapses(user.id, neuron.id, inferenceResult.prerequisites)`
   - Wrap in try/catch — on failure, log warning and return neuron without synapses

9. **Langfuse flush:** In a `finally` block, call `langfuseProcessor.forceFlush()` (matches bloom-evaluate route pattern for non-streaming JSON routes)

10. Return 201 with `{ neuron, synapses }` where synapses is the array of created synapse records (fetch from DB after insert) or empty array on Inquisitor failure.

**Error handling summary (per CONTEXT.md):**
- Synthesizer failure -> return 500
- RAG failure -> skip prerequisites, create orphan neuron
- Inquisitor failure -> skip prerequisites, create orphan neuron
- Success -> return 200 with { neuron, synapses }

To fetch synapses for the response, after createPrerequisiteSynapses returns the linked titles, query `supabase.from('synapses').select('*').eq('target_neuron_id', neuron.id)` to get the full synapse records the client needs for graph edges.

# Phase 999.1: Bloom Keyword Highlighting Animation - Context

**Gathered:** 2026-04-03
**Status:** Ready for planning

<domain>
## Phase Boundary

After the user sends a message, animate and highlight the key phrases the Bloom evaluator considered for classification. Provides real-time cognitive depth feedback directly in the chat message text. Does not change the evaluator's classification logic or the Generate Neuron button behavior.

</domain>

<decisions>
## Implementation Decisions

### Keyword Extraction
- **D-01:** Extend the Bloom evaluator's JSON response schema to include a `key_phrases` array. The LLM already analyzes the messages — extracting phrases costs near-zero extra tokens. Returns e.g. `["compared tradeoffs", "because the bottleneck"]`
- **D-02:** Update the `BLOOM_EVALUATOR_PROMPT` in `src/app/api/bloom-evaluate/route.ts` to instruct the model to return `key_phrases` alongside `bloom_level`, `confidence`, and `reasoning`
- **D-03:** Update the client-side fetch in `ChatPanel.tsx` `triggerBloomEval` to consume and store `key_phrases` in Zustand state

### Visual Treatment
- **D-04:** Keywords get a soft semi-transparent background tint in the Bloom level color (e.g., `bg-amber-400/10` for Analyze). No bold, no underline — background glow only
- **D-05:** Reuse the existing Bloom color palette from `GenerateNeuronButton` (sky → teal → emerald → amber → orange → yellow) for consistency
- **D-06:** No tooltip or hover interaction — the color alone conveys meaning. Keeps the implementation simple and the UX non-intrusive

### Highlight Scope
- **D-07:** Only highlight keywords in the most recent user message. Previous messages stay clean
- **D-08:** When a new Bloom evaluation arrives, clear any existing highlights from the previous message before applying new ones
- **D-09:** Assistant messages are never highlighted — only user messages show keywords

### Animation Timing & Trigger
- **D-10:** All keyword highlights in the message fade in simultaneously over ~300ms when the evaluator returns. Uses `transition-colors duration-300` or equivalent — matches the existing transition pattern in the codebase
- **D-11:** Highlights fade out automatically after ~5 seconds. The message text returns to normal. Draws momentary attention then disappears
- **D-12:** The evaluator fires ~500ms after the assistant response finishes (existing debounce), plus LLM latency. Highlights appear asynchronously — the user may have already read their message before highlights arrive, which is fine

### Claude's Discretion
- Exact Tailwind opacity value for the background tint (e.g., `/10` vs `/15`)
- How to match `key_phrases` against the message text (exact string match, case-insensitive, or fuzzy)
- Whether to wrap matched phrases in `<mark>` elements or use a React-based inline highlighting approach
- Exact fade-out implementation (CSS transition vs setTimeout + state toggle)
- Bloom evaluator prompt wording for the `key_phrases` extraction instruction
- Promptfoo eval case updates to validate the new `key_phrases` field

</decisions>

<specifics>
## Specific Ideas

- The "soft background glow" should feel like a gentle wash of color — think syntax highlighting in a code editor but more subtle. Not a solid highlight block
- The 5-second fade-out creates a "momentary awareness" effect — user notices the feedback, absorbs it, then it recedes. Avoids visual clutter in long conversations
- The existing Bloom color progression (cool → warm as depth increases) already communicates "deeper = warmer" intuitively
- Danish Computation aesthetic applies — this feature should feel observational, not gamified. The highlighting reveals what the AI noticed, not what the user "scored"

</specifics>

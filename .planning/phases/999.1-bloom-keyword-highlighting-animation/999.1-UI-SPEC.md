### Bloom Highlight Color Palette (this phase — new)

Source: D-04, D-05, RESEARCH.md Pattern 5, `GenerateNeuronButton.tsx` lines 70-81.

The accent in this phase is the Bloom level color. It is reserved exclusively for keyword highlight backgrounds on the latest user message during the 5-second display window.

| Bloom Level | Background Tint Class | Hex Approximate | Opacity Rationale |
|-------------|----------------------|-----------------|-------------------|
| Remember | `bg-sky-400/10` | sky-400 at 10% | Cooler color — readable at /10 |
| Understand | `bg-teal-400/10` | teal-400 at 10% | Cooler color — readable at /10 |
| Apply | `bg-emerald-400/10` | emerald-400 at 10% | Cooler color — readable at /10 |
| Analyze | `bg-amber-400/15` | amber-400 at 15% | Warmer color on dark bg — use /15 per RESEARCH.md open question resolution |
| Evaluate | `bg-orange-400/15` | orange-400 at 15% | Warmer color on dark bg — use /15 |
| Create | `bg-yellow-300/15` | yellow-300 at 15% | Warmest — use /15 |

**Opacity decision (Claude's Discretion):** Use `/10` for cool-toned levels (Remember, Understand, Apply) and `/15` for warm-toned levels (Analyze, Evaluate, Create). The chat panel background is `neural-gray-900/30` (very dark). At `/10`, warm colors like amber and orange are nearly invisible against `#111111`. `/15` provides the "gentle wash" described in CONTEXT.md specifics without exceeding the "soft glow" aesthetic intent.

**Accent reserved for:** Keyword highlight spans on the latest user message only, during the 5-second active window after Bloom evaluation resolves. No other UI element should use these tint classes.

**The color alone conveys meaning** (D-06). No tooltip, no hover state, no legend. The Bloom level color is already communicated by the existing `GenerateNeuronButton` badge. The keyword highlighting extends that same vocabulary into the message text.

### Tailwind Safelist Note

Because these classes are constructed dynamically via a `bloomToHighlightClass()` switch function, the executor MUST add these classes to the Tailwind `safelist` in `tailwind.config.ts` to prevent purging:

```

  'bg-emerald-400/10',
  'bg-amber-400/15',
  'bg-orange-400/15',
```

## Animation Contract

Source: D-10, D-11, D-12, RESEARCH.md Pattern 3, animate skill.

### Fade-In (highlight entrance)

| Property | Value | Rationale |
|----------|-------|-----------|
| Technique | Tailwind `transition-colors duration-300` | D-10 explicitly names this pattern; matches project-wide transition convention |
| Duration | 300ms | `duration-300` |
| Easing | CSS default for `transition-colors` (linear) | Background color transitions do not require custom easing — the change is subtle enough |
| Trigger | Zustand `bloomKeyPhrases` becomes non-empty; `isHighlighted` local state set to `true` | React re-render toggles the background tint class on/off |
| Initial state | No background (`bg-transparent` / no class) | Spans render without highlight class initially |
| Active state | Background tint class applied (per level table above) | `isHighlighted === true` gates class application |

**Do not use Framer Motion** for this specific animation. `transition-colors duration-300` is idiomatic (D-10, RESEARCH.md state of the art). Framer Motion is installed and used elsewhere but is unnecessary overhead here.

### Fade-Out (auto-dismiss)

| Property | Value | Rationale |
|----------|-------|-----------|
| Duration | 5 seconds after `isHighlighted` set to `true` | D-11 |
| Mechanism | `useEffect` + `setTimeout(5000)` → `setIsHighlighted(false)` | RESEARCH.md Pattern 3 — component-level state, not Zustand |
| Visual transition | Same `transition-colors duration-300` — background returns to transparent | Symmetric fade; same easing |
| Cleanup | `clearTimeout` in `useEffect` cleanup return | Prevents timer from firing after unmount or re-trigger |

### Trigger Timing (informational, not a UI contract)

| Event | Timing |
|-------|--------|
| Bloom evaluator fires | ~500ms after assistant response finishes (existing debounce) |
| LLM latency | Variable (500ms–2s typical) |
| Highlights appear | Async — user may have already scrolled past their message |
| Total highlight window | 5 seconds from appearance |

This is acceptable per D-12. The feature is observational, not attention-critical.

### Accessibility

Apply `prefers-reduced-motion` respect per animate skill:

- When `prefers-reduced-motion: reduce` is active, set `transition-duration` to `0.01ms` or disable the `transition-colors` class entirely. The highlight should still appear and disappear — just instantly rather than animated.
- The highlight is purely decorative (no information is lost if it doesn't animate).
- Suggested implementation: conditionally apply `transition-colors duration-300` vs `transition-none` based on `window.matchMedia('(prefers-reduced-motion: reduce)').matches`, or use a Tailwind `motion-reduce:transition-none` utility class.

## Component Behavior Contract

### `renderHighlightedText` function

| Behavior | Specification |
|----------|--------------|
| Input | `text: string`, `phrases: string[]`, `isHighlighted: boolean`, `highlightClass: string` |
| Match strategy | Case-insensitive exact substring match using capturing-group regex (`gi` flag) |
| Match technique | `String.split()` with capturing group regex — odd-indexed elements are matched phrases (avoids `lastIndex` drift) |
| Phrase escaping | Each phrase escaped with `phrase.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')` before regex construction |
| No-match behavior | Returns plain text string (no spans) — silent failure, never throws |
| Span element | `<span>` (not `<mark>`) — `<mark>` carries browser default yellow styling; use `<span>` with explicit class |
| Span classes on match | `rounded-sm transition-colors duration-300 {highlightClass}` when `isHighlighted`, `rounded-sm transition-colors duration-300` when not |
| Span classes on non-match | Plain `<span>` with no classes |

### `useBloomHighlight` hook

| Behavior | Specification |
|----------|--------------|
| Zustand selectors | `bloomKeyPhrases`, `latestBloomMessageId`, `bloomLevel` — one selector per field (per project pattern) |
| Local state | `isHighlighted: boolean` — local to component, not Zustand |
| Timer | `useEffect` watching `bloomKeyPhrases` — `setTimeout(5000)` to clear `isHighlighted` |
| Reset trigger | `bloomKeyPhrases.length === 0` sets `isHighlighted(false)` immediately — handles conversation switch |

### Highlight scope enforcement

| Rule | Mechanism |
|------|-----------|
| Only latest user message | Check `message.id === latestBloomMessageId` before calling `renderHighlightedText` |
| Previous messages stay clean | All other user messages render `part.text` as plain string — no split, no spans |
| Assistant messages excluded | D-09: assistant messages use ReactMarkdown — never pass to `renderHighlightedText` |
| Message ID captured at trigger time | `triggerBloomEval` stores `messagesRef.current.filter(m => m.role === 'user').at(-1)?.id` at the moment of firing (prevents race condition) |

## Copywriting Contract

This phase does not introduce new UI copy surfaces. There is no CTA, empty state, error state, or destructive action in the user-facing sense. The feature is entirely invisible to the user unless a Bloom evaluation succeeds and `key_phrases` are returned.

| Element | Copy | Notes |
|---------|------|-------|
| Primary CTA | None | No new button or user action introduced |
| Empty state | None | Feature is additive to existing chat; no new empty state |
| No-phrases state | Silent (no highlight rendered) | If `key_phrases` is empty or no matches found in text — no error message, no fallback UI |
| Error state | Silent (no highlight rendered) | If Bloom evaluator fails to return `key_phrases`, default to `[]` — no user-visible error for this field specifically |
| Destructive actions | None | Feature introduces no destructive actions |

**Aesthetic alignment:** The feature is "observational, not gamified" (CONTEXT.md specifics). No copy is needed because the feature reveals itself and recedes. Adding labels like "Keywords detected" would violate the Danish Computation aesthetic — it would make the tool feel like it is scoring the user.

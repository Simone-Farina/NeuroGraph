# Phase 999.2: Pretext Integration Evaluation

**Date:** 2026-04-03
**Library:** `@chenglou/pretext` v0.0.4 (chenglou/pretext)
**Verdict: NO-GO — Pretext is a text measurement library with no overlap to NeuroGraph's needs**

---

## 1. What Pretext Is

Pretext is a pure JavaScript/TypeScript **text measurement and layout library** authored by chenglou (creator of ReasonML, React Motion). It computes multiline text height and line layout using cached font metrics — without touching the DOM and without triggering browser reflow.

- **npm:** `@chenglou/pretext` — version 0.0.4, published 2026-04-01
- **Maturity:** pre-alpha (`0.0.x` semver — explicitly unstable API)
- **Dependencies:** Zero runtime dependencies
- **License:** MIT

**Core API:**
```typescript
import { prepare, layout } from '@chenglou/pretext'
const prepared = prepare('your text', '16px Inter')
const { height, lineCount } = layout(prepared, containerWidth, lineHeight)
```

**Target use cases:** virtualized lists requiring pre-render height measurements, canvas/SVG/WebGL text rendering (no DOM available), masonry layout algorithms, and development-time layout verification.

**What it is NOT:** not a markdown renderer, not a React component, not an AI SDK, not a streaming protocol handler, not a rich text editor, not a replacement for react-markdown or TipTap.

## 3. Comparison to Current Stack

Pretext and react-markdown solve entirely different problems. They are orthogonal tools that could theoretically coexist — but Pretext adds nothing to NeuroGraph's current rendering pipeline.

| Dimension | react-markdown (current) | Pretext (candidate) | Verdict |
|-----------|--------------------------|---------------------|---------|
| Markdown parsing → React elements | Yes — full GFM, code, tables | No — does not render | react-markdown wins |
| Streaming compatibility | Yes — rerenders on each token delta | N/A — no render concept | react-markdown wins |
| DOM reflow prevention | N/A — renders to DOM | Yes — avoids reflow for measurement | Only useful for virtualized lists |
| Syntax highlighting | Yes via rehype-highlight | No | react-markdown wins |
| Maturity | Stable, widely used | 0.0.4 pre-alpha | react-markdown wins |

TipTap (ProseMirror): self-manages layout internally. Pretext has no interaction surface with it.

Vercel AI SDK: server-side streaming protocol. Pretext operates at the browser layout layer. Zero overlap.

## 5. Go/No-Go Verdict

**Verdict: NO-GO**

Three clear reasons:

1. **Wrong domain.** Pretext measures text dimensions. NeuroGraph's text need is markdown-to-React rendering. These are different problems — adopting Pretext alongside react-markdown would add complexity with zero benefit.

2. **No problem to solve.** Pretext's value lies in avoiding DOM reflow for expensive text layout measurements in virtualized lists, canvas, or masonry contexts. NeuroGraph has none of these. Chat messages render as natural DOM flow; no measurement step exists in the pipeline.

3. **Pre-alpha risk.** Version 0.0.4 (`0.0.x` semver) signals an explicitly unstable API. The inline-flow module is marked alpha within a pre-alpha package. Adopting this without a pressing use case is unjustifiable risk.

Per D-04: this is an early dismissal. The conclusion is clear from initial research — no deeper analysis is warranted.

## 6. Conditions for Future Reconsideration

Revisit only if ALL of the following apply:

- (a) NeuroGraph implements a **virtualized message list** with measured, documented layout performance problems
- (b) OR NeuroGraph adds **canvas or WebGL rendering** for chat output
- (c) AND Pretext reaches **1.0.0** with a stable, production-ready API

None of these conditions are close to materializing in the current roadmap (v2.2 QA Refinement III and beyond are bug-fix focused, not rendering-architecture focused).

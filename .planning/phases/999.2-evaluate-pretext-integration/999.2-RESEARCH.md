## Summary

Pretext (`@chenglou/pretext`, https://github.com/chenglou/pretext) is a **pure JavaScript/TypeScript text measurement and layout library** — not an AI conversation library, not a markdown renderer, and not a chat UI framework. Its core value proposition is measuring multiline text height and performing line layout calculations using the browser's font engine as ground truth, entirely without touching the DOM (no `getBoundingClientRect`, no reflows).

The library is authored by chenglou (creator of ReasonML and React Motion), published on npm as `@chenglou/pretext` at version 0.0.4 (published 2026-04-01, two days ago as of this research), and is in active early development with 286 commits. It has zero runtime dependencies.

**Primary finding:** Pretext solves a real problem — expensive DOM reflows during text layout measurement — but that problem does not exist in NeuroGraph's current architecture. NeuroGraph renders chat messages using `react-markdown` inside a standard scrollable div. It does not perform custom text measurement, virtualized list rendering, canvas text rendering, or any layout operation that would benefit from pre-DOM text sizing. The library's capabilities are entirely orthogonal to what `react-markdown`, TipTap, and the Vercel AI SDK provide.

**Primary recommendation:** No-Go. Pretext is a specialized text measurement tool for a performance problem NeuroGraph does not have. No migration is warranted.

## What Pretext Actually Is

**Confidence: HIGH** — verified against npm registry (version 0.0.4, published 2026-04-01), GitHub repo (286 commits, last commit 2026-04-02), and official README.

### Category
Text measurement and layout library. Specifically: a library for computing text dimensions (height, line count, line boundaries) without triggering browser layout reflow.

### Core Problem It Solves
DOM measurement APIs (`getBoundingClientRect`, `offsetHeight`, `scrollHeight`) cause synchronous layout reflow. In high-frequency scenarios — virtualized lists, canvas rendering, masonry layouts, text wrapping around floats — these reflows are expensive. Pretext caches font metrics once and performs subsequent layout math as pure arithmetic.

### Public API (as of v0.0.4)
```typescript
// Primary path: measure text height
import { prepare, layout } from '@chenglou/pretext'

const prepared = prepare('your text', '16px Inter')
// Expensive once, cheap forever:
const { height, lineCount } = layout(prepared, containerWidth, lineHeight)

// Advanced path: manual line-by-line layout
import { prepareWithSegments } from '@chenglou/pretext'
const prepared = prepareWithSegments('text', '16px Inter')
layoutWithLines(prepared, maxWidth)       // all lines at once
walkLineRanges(prepared, maxWidth, fn)    // iterate without building strings
layoutNextLine(prepared, fn)             // streaming variable-width layout

// Alpha sidecar: mixed inline runs (e.g., text + chip + icon)
import { prepareInlineFlow } from '@chenglou/pretext/inline-flow'
```

### Target Use Cases
- Virtualized lists that need accurate item heights before render
- Canvas / SVG / WebGL text rendering (no DOM available)
- Masonry and custom layout algorithms
- Development-time layout verification (catches font-dependent wrapping bugs)
- Text flowing around floated elements

### What It Is NOT
- Not a markdown parser or renderer
- Not a React component library
- Not an AI SDK or streaming protocol handler
- Not a rich text editor
- Not a replacement for react-markdown, TipTap, or the Vercel AI SDK

### What react-markdown Does That Pretext Does Not
`react-markdown` converts a markdown string into React elements (`<p>`, `<h1>`, `<code>`, etc.) with full AST processing, plugin support (remark/rehype ecosystem), and streaming-compatible incremental rendering. It is a markdown-to-DOM renderer. Pretext does not parse markdown, does not produce React elements, and does not render anything — it only measures.

### Chat Rendering Architecture Notes
- Chat messages are rendered in a simple `<div className="space-y-4">` with natural CSS flow
- No virtualization — messages render as full DOM elements; list grows naturally
- No canvas or SVG rendering
- No custom text measurement needed
- Bloom keyword highlighting is done via string split + `<span>` wrapping (renderHighlightedText in MessageList.tsx) — pure React, no measurement needed
- Streaming text arrives as token chunks; react-markdown re-renders incrementally on each `messages` state update

## Compatibility Risk Assessment (D-09)

**Confidence: HIGH**

Since Pretext is a measurement utility (not a renderer, not a state manager, not a protocol handler), it has zero interaction surface with:

- **Langfuse OTel tracing** — Pretext operates in the browser render layer; tracing wraps server-side AI calls. No conflict.
- **OpenRouter routing** — Server-side model routing; entirely separate from client text layout. No conflict.
- **Zustand state (graphStore, chatStore)** — State management is unaffected by text measurement. No conflict.
- **Streaming protocol** — Vercel AI SDK's UIMessage stream is consumed by ChatPanel; Pretext would be called (if at all) after text is rendered, not during streaming. No conflict in theory, but no benefit either.

The compatibility risk is zero — but so is the benefit.

## Common Pitfalls for This Evaluation

### Pitfall 1: Confusing "text" in the library name with "text rendering"
**What goes wrong:** Assuming a "text measurement" library replaces "text rendering" tools.
**Reality:** Pretext measures layout dimensions. react-markdown renders content. These are orthogonal operations. A hypothetical integration would add Pretext alongside react-markdown, not instead of it — and only if virtualization were needed.

### Pitfall 2: Assuming pre-alpha (0.0.x) means "almost ready"
**What goes wrong:** Planning a migration to a library at 0.0.4 on the assumption it will stabilize soon.
**Reality:** `0.0.x` is below `0.x.x`. API surface is explicitly unstable. The inline-flow API is marked alpha. No adoption guarantee.

### Pitfall 3: Solving a performance problem that doesn't exist
**What goes wrong:** Adopting a reflow-prevention library when reflows are not occurring at meaningful frequency.
**Reality:** NeuroGraph's chat list is not virtualized and does not need to be at current scale. react-markdown renders each message as natural DOM flow. No measurement step exists in the pipeline.

## Go/No-Go Recommendation

**Verdict: NO-GO**

**Reasoning:**

1. **Wrong domain.** Pretext is a text measurement library. NeuroGraph's chat rendering need is markdown-to-React conversion. These are different problems. Pretext does not compete with or improve upon react-markdown.

2. **No problem to solve.** The library's core value — avoiding DOM reflow during text layout measurement — requires a use case that generates expensive measurements: virtualized lists, canvas rendering, or masonry layouts. NeuroGraph has none of these in the chat path.

3. **Pre-alpha risk.** Version 0.0.4 with an explicitly unstable API is not appropriate for production integration without a specific pressing need that justifies the stability risk. No such need exists.

4. **Zero overlap with AI/streaming stack.** Pretext has no interaction with the Vercel AI SDK, streaming protocol, or any AI-layer concern. The library name may have suggested an AI "pretext" — it is not that.

**Conditions that would change the verdict (future reconsideration):**
- If NeuroGraph implements a virtualized message list (thousands of messages, performance measured as problematic)
- If NeuroGraph adds a canvas or WebGL rendering mode for chat
- If Pretext reaches 1.0.0 with stable APIs and the above use cases emerge

**Migration sketch:** Not applicable (No-Go verdict).
